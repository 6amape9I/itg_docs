# N2.1. Доработка candidate generation перед LLM-валидацией N3

## 0. Контекст

Этап N2 технически реализован: создан пакет `kb_rebuild/normalization/n2`, CLI-команда `normalize-n2`, candidate nodes, candidate pairs, candidate groups, blocked/rejected pairs, report и manifest.

Но текущий N2 нельзя принимать как готовый вход для N3, потому что candidate filtering слишком либеральный. В `candidate_groups.csv` попадают ложноположительные группы:

- базовый метод + анатомически/объектно уточнённый метод;
- разные методы с одинаковой аббревиатурой;
- разные болезни с одинаковым родовым словом и разной локализацией;
- процедуры вида “вакцинация против X” и “вакцинация против Y”;
- `blocked_review` groups смешаны с обычными N3-кандидатами.

N2.1 должен улучшить качество candidate groups, чтобы N3 получал меньше мусора и больше настоящих alias-кандидатов.

## 1. Цель N2.1

Цель N2.1 — сделать candidate generation пригодным для N3.

Нужно:

1. Отделить реальные N3-candidates от blocked/review groups.
2. Ужесточить правила `recommended_for_n3`.
3. Убрать ложные high-priority groups из-за generic aliases.
4. Ужесточить abbreviation matching.
5. Добавить parent-child / scope-conflict detection для diagnostic methods, procedures, diseases и других типов.
6. Добавить hub-node protection.
7. Сохранить полезные candidate groups, но пометить рискованные отдельно.
8. Обновить отчёты, CSV и tests.

## 2. Не цели N2.1

На N2.1 запрещено:

- вызывать LLM;
- создавать финальные `tags_canonical.csv`;
- создавать финальные `tag_aliases.csv`;
- создавать финальные `document_tag_links_normalized.jsonl`;
- принимать финальные merge-решения;
- изменять `data/tagging/*`;
- изменять N1.1 outputs;
- запускать N3;
- запускать evidence/article pipeline.

## 3. Текущие проблемы, которые нужно исправить

### 3.1 Слишком широкое `exact_normalized_match`

Сейчас `exact_normalized_match` может срабатывать, если совпал любой normalized alias внутри node. Это опасно.

Пример плохого результата:

```text
Магнитно-резонансная томография
МРТ гипофиза
МРТ позвоночника
МРТ молочных желез

Если у специфичных методов есть alias магнитно-резонансная томография, это не значит, что они являются одной сущностью.

3.2 Аббревиатуры слишком сильные

Пример плохого результата:

Квантифероновый тест
Компьютерная томография
Кератотопография

Все могут давать КТ, но это разные сущности.

Аббревиатуры вроде КТ, МРТ, УЗИ, ПЦР, ИФА, ЭКГ, ЭЭГ не должны автоматически давать high-priority candidate, если сокращение просто сгенерировано алгоритмом.

3.3 Parent-child не блокируется для diagnostic_method/procedure

Примеры плохих candidates:

МРТ
МРТ гипофиза
МРТ позвоночника
Рентгенография
Рентгенография зубов
Рентгенография органов грудной клетки
Биопсия
Биопсия кожи
Биопсия почки

Это не aliases, а базовый метод + уточнённая область/объект.

3.4 Разные локализации болезней

Пример плохих candidates:

Полип матки
Полип носа
Полип шейки матки

Это разные заболевания/локализации, не alias одной сущности.

3.5 Разные профилактические процедуры

Пример плохих candidates:

Вакцинация против гепатита А
Вакцинация против жёлтой лихорадки
Вакцинация против клещевого энцефалита
Вакцинация против паротита

Это разные сущности, а не варианты названия одной процедуры.

3.6 blocked_review смешан с candidates

Сейчас candidate_groups.csv содержит и обычные candidates, и 5 000 blocked_review groups. Для N3 это неудобно.

N3 должен читать только чистый файл с кандидатами, рекомендованными к LLM-валидации.

4. Основное архитектурное изменение

Добавить явный статус группы:

candidate_group_status

Возможные значения:

n3_candidate
low_confidence_candidate
blocked_review
hub_parent_child_suspect
ambiguous_abbreviation
generic_alias_conflict
4.1 n3_candidate

Группа годится для N3 LLM validation.

Условия:

нет hard blocking reasons;
не both_context_only;
нет generic alias conflict;
нет hub parent-child conflict;
есть достаточно сильная alias-гипотеза;
группа не является очевидным parent/child набором.
4.2 low_confidence_candidate

Группа потенциально полезна, но слабая. В N3 по умолчанию не идёт.

4.3 blocked_review

Группа содержит blocked pair или hard conflict. В N3 не идёт.

4.4 hub_parent_child_suspect

Группа вокруг общего метода/болезни/процедуры, где есть множество уточнённых дочерних сущностей.

Примеры:

МРТ ↔ МРТ гипофиза
Рентгенография ↔ Рентгенография зубов
Биопсия ↔ Биопсия кожи
4.5 ambiguous_abbreviation

Группа создана из-за неоднозначной аббревиатуры без явного evidence.

Пример:

КТ = компьютерная томография / квантифероновый тест / кератотопография
4.6 generic_alias_conflict

Группа создана из-за совпадения generic alias, но canonical labels разные и один label является уточнением другого.

7. Ужесточить recommended_for_n3

Сейчас recommended_for_n3=true слишком часто.

Новое правило:

recommended_for_n3=true

только если:

candidate_group_status=n3_candidate;
group_priority in high|medium;
нет hard blocking reasons;
нет both_context_only, кроме случаев с сильным явным alias evidence;
нет parent_child_suspect, кроме product variants;
нет generic_alias_conflict;
нет ambiguous_abbreviation;
нет hub explosion;
есть хотя бы один strong clean reason.
Разрешённые strong clean reasons
explicit_parenthetical_alias_match
explicit_alias_exact_match
shared_latin_candidate_non_short
product_variant_match
known_safe_abbreviation_match
high_sequence_similarity_without_scope_conflict
Не считать clean strong reason
exact_normalized_match
abbreviation_match

если они получены только из generic aliases или generated acronyms.

8. Исправить exact normalized match
8.1 Проблема

Сейчас exact match по любому alias считается сильным.

8.2 Новая модель exact-match features

Разделить exact match на:

primary_label_exact_match
canonical_alias_exact_match
generic_alias_exact_match
8.3 Правила

primary_label_exact_match — сильный сигнал.

Пример:

Болезнь Аддисона
Болезнь Аддисона

canonical_alias_exact_match — средне/сильный сигнал, если alias не generic.

Пример:

generic_alias_exact_match — НЕ strong reason.

Пример:

Магнитно-резонансная томография

Если совпал только общий generic alias, pair должен получить:

generic_alias_conflict

или parent_child_suspect.

10. Scope conflict detection

Добавить модуль или функции:

scope_conflict.py

Или в blocking.py.

Цель: находить случаи, где один термин является базовым методом/болезнью/процедурой, а другой — уточнённой сущностью.

16. Hub-node protection
16.1 Проблема

Один node, например:

Магнитно-резонансная томография

может входить в 10+ recommended groups. Это признак hub parent-child explosion.

16.2 Новое правило

После построения groups посчитать:

node_recommended_group_count

Если node входит в слишком много N3-ready groups, например:

> 5

и причины в основном generic alias / parent-child / same generic method, то:

снять n3_ready;
поставить candidate_group_status=hub_parent_child_suspect;
записать в hub_parent_child_suspects.csv.
16.3 Исключение

Если node — реальная аббревиатура с несколькими aliases одной сущности, например:

ИФА
иммуноферментный анализ
ELISA

и группа компактная, не считать hub explosion.

# Задача

Ты валидируешь, являются ли несколько тегов одной и той же медицинской сущностью.

Будь строгим. N2 уже отфильтровал много мусора, но N3 не должен автоматически принимать похожие строки. Принимай merge только когда все элементы явно обозначают одну и ту же сущность.

Верни строго один JSON-объект по schema. Не используй markdown. Не объясняй ход рассуждений. В поле `reason` дай короткое проверочное объяснение решения.

## Решения

- `accept_same_entity`: все labels/nodes в группе являются одной сущностью.
- `reject_distinct_entities`: группа не содержит полезного merge.
- `split_into_subclusters`: есть полезный alias-subcluster, но в группе есть лишние или отдельные элементы.
- `needs_web_or_human_review`: без внешней проверки или ручного решения уверенно решить нельзя.

## Строгие запреты

Не объединяй:

- родительскую и дочернюю сущность;
- базовый метод и метод с локализацией или объектом;
- болезни с разной локализацией;
- болезни с разными типами, подтипами, стадиями, группами или буквенными вариантами;
- разные вирусы, серотипы, штаммы или группы микроорганизмов;
- разные торговые продукты;
- разные БАДы одной линейки или бренда;
- процедуры с разным объектом применения;
- лекарство и класс лекарств;
- торговое название и действующее вещество;
- широкий класс и подкласс.

Если хотя бы один элемент явно отличается от остальных, не возвращай `accept_same_entity`. Используй `split_into_subclusters` или `reject_distinct_entities`.

## Что можно объединять

Можно объединять:

- русское и латинское название одной сущности;
- синонимы;
- эпонимические варианты;
- аббревиатуру и полное название, если это именно одно и то же;
- орфографические варианты;
- варианты регистра;
- варианты с или без скобочного alias;
- торговое название с дозировкой и без дозировки, если это тот же продукт;
- БАД с дозировкой и без дозировки, если это тот же продукт.

## Примеры

`[Мерцательная аритмия, Фибрилляция предсердий, Мегалобластная анемия]`

Решение: `split_into_subclusters`

Subclusters:

- `[Мерцательная аритмия, Фибрилляция предсердий]`
- `[Мегалобластная анемия]`

`[Гемофилия A, Гемофилия А, Гемолитическая анемия]`

Решение: `split_into_subclusters`

Subclusters:

- `[Гемофилия A, Гемофилия А]`
- `[Гемолитическая анемия]`

`[Вирус гепатита A, Вирус гепатита B, Вирус гепатита C]`

Решение: `reject_distinct_entities`

`[Жевательный кальций RBC, Железо RBC, Люцерна RBC]`

Решение: `reject_distinct_entities`

`[Аддисонова болезнь, Болезнь Аддисона]`

Решение: `accept_same_entity`

## Web search

Web search по умолчанию не используется. Если без внешней проверки нельзя уверенно решить, верни `needs_web_or_human_review`.

## JSON shape

Верни объект:

```json
{
  "candidate_group_id": "cg_000001",
  "decision": "accept_same_entity",
  "confidence": 0.95,
  "canonical_tag_ru": "Болезнь Аддисона",
  "canonical_tag_latin": "Addison disease",
  "entity_type": "disease",
  "subclusters": [
    {
      "subcluster_id": "sc_001",
      "decision": "same_entity",
      "canonical_tag_ru": "Болезнь Аддисона",
      "canonical_tag_latin": "Addison disease",
      "labels": ["Аддисонова болезнь", "Болезнь Аддисона"],
      "node_ids": ["n_000001", "n_000002"],
      "confidence": 0.95,
      "reason": "синонимические эпонимические варианты одной болезни"
    }
  ],
  "rejected_labels": [],
  "reason": "все labels обозначают одну сущность",
  "risk_flags": [],
  "requires_human_review": false
}
```
